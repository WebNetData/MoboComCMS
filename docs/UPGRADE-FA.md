# آپدیت موبوکام از پنل وب

نصب بسته‌ای برای آپدیت به GitHub، Git یا توکن توسعه نیاز ندارد. فایل انتشار می‌تواند از هاست دانلود خودتان دریافت شود؛ روی سرور سایت فقط از پنل استفاده می‌کنید.

**محل دریافت نسخه:** [GitHub Releases موبوکام](https://github.com/WebNetData/MoboComCMS/releases) ← نسخهٔ موردنظر ← Assets ← `mobocom-VERSION.mbrelease`. مخزن خصوصی است؛ با حساب دارای دسترسی روی کامپیوتر دانلود و از پنل سایت بارگذاری کنید. گزینهٔ Source code/Download ZIP قابل نصب در آپدیتر نیست. بستهٔ امضاشده شامل سورس ثبت‌شده است و سرور بیلد سازگار با محیط خودش را آماده می‌کند؛ این کار حافظه، دیسک و دسترسی به مخازن وابستگی‌ها می‌خواهد. [روند کامل توسعه → انتشار → آپدیت](RELEASES-FA.md).

## آپدیت معمول

1. فایل mbrelease نسخهٔ جدید را از ناشر مورد اعتماد بگیرید.
2. در **پنل سرور ← به‌روزرسانی امن** با گذرواژه پنل را باز کنید.
3. فایل را انتخاب و «بارگذاری و بررسی بسته» را بزنید. سقف ۵۱۲ مگابایت است؛ سایت هنوز تغییر نمی‌کند.
4. نسخه و مشخصات ناشر را بررسی کنید، تأیید پشتیبان‌گیری را بزنید و نصب را شروع کنید.

امضای ناشر دیگر، فایل دستکاری‌شده، نسخهٔ مساوی/قدیمی و حجم اضافی پذیرفته نمی‌شود. حداکثر دو بسته آماده نگه داشته می‌شود؛ پس از تازه‌کردن صفحه باقی می‌مانند و پیش از نصب قابل حذف‌اند.

نسخهٔ جدید جداگانه ساخته می‌شود. پیش از تعویض کد، بکاپ PostgreSQL و فایل‌ها اجباری است؛ شکست بکاپ مانع تعویض کد می‌شود. سرویس برای جایگزینی دوباره راه‌اندازی و سلامت آن بررسی می‌شود. مهاجرت‌ها همان مسیر موجود آغاز سرویس را دارند. این روش تضمین بدون‌قطعی نیست.

شکست ساخت/بکاپ سایت فعلی را حفظ می‌کند. شکست راه‌اندازی/سلامت پس از تعویض، کد قبلی را برمی‌گرداند و سلامت آن را هم بررسی می‌کند. دیتابیس خودکار عقب نمی‌رود؛ سازگاری مهاجرت با نسخهٔ قبلی باید در همان انتشار تأیید شود. اگر نسخهٔ قبلی هم سالم بالا نیاید، وضعیت ناموفق می‌ماند و اپراتور باید لاگ را بررسی کند.

فایل‌های کاربران، storage، var، env و اسرار سرور جایگزین نمی‌شوند. فایل‌های قدیمی public/demo و public/uploads هم در نشانی قبلی حفظ می‌شوند؛ این مسیرهای قدیمی و فضاهای بیرونی به پشتیبان جداگانه نیاز دارند، چون بکاپ میزبان storage را پوشش می‌دهد. DOWNLOADS_ROOT سفارشی داخل پوشهٔ کد و خارج از مسیرهای دادهٔ حفاظت‌شده باعث توقف امن و درخواست بررسی اپراتور می‌شود. ویرایش محلی کد یا فایل جدید خارج از نسخهٔ نصب‌شده، آپدیت را متوقف می‌کند تا کار شما پاک نشود. کد قبلی در مسیر خصوصی .package.*/before کنار برنامه می‌ماند. پس از تأیید نسخهٔ جدید، اپراتور می‌تواند نسخه‌های اضافی را با بررسی مسیر حذف کند. شکست‌های پیش از تعویض هم ممکن است پوشهٔ ساخت را باقی بگذارند؛ فضای دیسک را پایش کنید.

## نصب نیمه‌تمام پیش از ساخت مدیر

گزینهٔ rootِ `--resume-uninstalled` در فایل نصب1.6.1 فقط برای کد قدیمی پیش از پایان نصب است؛ همان worker بسته‌ای با بکاپ اجباری، بررسی نبود مدیر و حفظ env/فایل‌ها اجرا می‌شود. این گزینه راه آپدیت یک سایت نصب‌شده نیست. [دستور و محدودیت‌ها](INSTALL-FA.md#ادامهٔ-نصب-نیمه‌تمام-قدیمی). ابزار root جدید و کلید ناشر فقط از bootstrap مورد اعتماد نصب می‌شوند؛ آپلود عادی بسته اختیار تعویض ابزار root یا ناشر را ندارد.

## پشتیبان و بازیابی داده

بکاپ میزبان خصوصی ولی رمزگذاری‌نشده است؛ با بکاپ رمزگذاری‌شدهٔ داخلی تفاوت دارد. یک نسخه را امن خارج از سرور نگه دارید و اسرار env را جدا پشتیبان بگیرید:

    sudo mobocom backup
    sudo mobocom backups

بازیابی آخرین راه است و داده‌های بعد از تاریخ بکاپ را عقب می‌برد. فقط پشتیبان مورد اعتماد خودتان را انتخاب کنید:

    sudo mobocom restore 20261031-033000

این دستور تأیید RESTORE می‌خواهد، کپی خصوصی آرشیو را بررسی می‌کند، سایت را متوقف و از وضعیت فعلی بکاپ می‌گیرد. تنظیمات اتصال و اسرار فعلی حفظ می‌شوند. شکست تراکنش دیتابیس فایل‌های قبلی را هم برمی‌گرداند. تراکنش دیتابیس شامل فایل‌سیستم نیست؛ قطع برق، خرابی دیسک یا kill -9 به بازیابی دستی نیاز دارد. قفل صرفاً به‌خاطر قدیمی‌بودن حذف نشود. workerها و نویسنده‌های بیرونی دیتابیس را پیش از بازیابی متوقف کنید.

بکاپ schema قدیمی ابتدا در محیط جدا آزمایش شود؛ جدول‌های اضافه‌شده بعد از آن خودکار حذف نمی‌شوند و اجرای دوبارهٔ مهاجرت‌ها ممکن است برخورد داشته باشد. تضمین خودکار برای تمام ترکیب‌های تاریخی نسخه‌ها وجود ندارد. خرابی منطقی نسخه‌ای که از health عبور کرده، نیازمند بازیابی کد از snapshot با بررسی اپراتور است؛ دکمهٔ نصب فقط ارتقا می‌دهد.

## انتقال نصب Git قدیمی

مسیر Git/tag قبلی حفظ شده است. برای فعال‌شدن بسته‌ها، اپراتور فایل run مورد اعتماد را یک بار روی مسیر استاندارد اجرا می‌کند؛ env و کد موجود بازنویسی نمی‌شوند و ابزار/کلید عمومی هم‌ناشر نصب می‌شود. برنامه باید نسخهٔ دارای بارگذاری بسته باشد؛ برنامه‌های قدیمی‌تر ابتدا از مسیر قبلی ارتقا یابند. اگر env قدیمی SERVER_PANEL_ENABLED=true ندارد، اپراتور آن را فعال و سرویس را دوباره راه‌اندازی می‌کند. اعتماد به ناشر و دسترسی root از فرم عادی Admin قابل تعویض نیست.

Nginx تازه location بسته با سقف ۵۱۲ مگابایت و streaming دارد. در تنظیم قدیمی/سفارشی، location نشانی /api/admin/server/updates/package را از deploy/ubuntu/nginx-mobocom.conf پس از بررسی به server مناسب اضافه و nginx -t را اجرا کنید؛ نصب‌کننده تنظیم سفارشی موجود را بازنویسی نمی‌کند. محدودیت CDN/پراکسی دیگر هم بررسی شود.

برای نصب Git، از جمله نصب با [دستور یک‌خطی](INSTALL-FA.md#نصب-با-یک-دستور):

    sudo mobocom update              # آخرین نسخه
    sudo mobocom versions            # نسخه‌های منتشرشده (tagهای vX.Y.Z) و نسخهٔ نصب‌شده
    sudo mobocom update 1.7.0        # یک نسخهٔ مشخص جدیدتر
    sudo mobocom downgrade 1.6.1     # یک نسخهٔ قدیمی‌تر؛ تأیید DOWNGRADE می‌خواهد
    sudo mobocom rollback            # نسخهٔ پیش از آخرین آپدیت

هر چهار مسیر از یک روال استفاده می‌کنند: بکاپ اجباری، تعویض کد، ساخت، بررسی سلامت و بازگشت خودکار به کد قبلی در صورت شکست. دیتابیس در برگشت نسخه عقب نمی‌رود. اگر نسخهٔ قدیمی با دیتابیس فعلی بالا نیاید، نسخهٔ فعلی خودبه‌خود برمی‌گردد. برای برگرداندن داده هم از بخش بازیابی بالا استفاده کنید. روی سروری که دستور `mobocom` آن قدیمی است، `curl -fsSL https://raw.githubusercontent.com/WebNetData/MoboComCMS/main/install.sh | sudo bash -s -- versions` دستور را تازه و اجرا می‌کند.

در نصب بسته‌ای، status/backup/restore بدون Git کار می‌کنند و update شما را به پنل وب هدایت می‌کند.

## Docker و Coolify

این میزبان‌ها همچنان از ایمیج/وب‌هوک خودشان استفاده می‌کنند؛ نصب بسته‌ای مخصوص Ubuntu/systemd است و داده‌ها باید volume دائمی داشته باشند. [Coolify](DEPLOY-COOLIFY.md) و [مالکیت داده](UPDATES-AND-DATA.md) را ببینید.

## برای نگهدارندهٔ انتشار

نسخهٔ جدید از کد بررسی‌شده با همان کلید خصوصی آفلاین ساخته شود؛ [ساخت فایل نصب](INSTALL-FA.md#ساخت-بسته-برای-ناشر). امضا از [Ed25519 در Node22](https://nodejs.org/docs/latest-v22.x/api/crypto.html) استفاده می‌کند. مسیر، نوع فایل و حدود بازکردن tar حتی پس از تأیید امضا بررسی می‌شوند؛ [مستندات Python](https://docs.python.org/3.10/library/tarfile.html) خطر استخراج بررسی‌نشده را توضیح می‌دهد.

نتایج اجراشده و محدودیت‌ها در [ادامهٔ کار بسته‌های وب](agent/handoffs/WEB_PACKAGE_UPDATES.md) ثبت شده‌اند.
