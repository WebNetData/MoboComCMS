# MoboCom 1.7.16

این نسخه تغییرات ادغام‌شدهٔ PR415 تا PR425 پس از ۱.۷.۱۵ را ارائه می‌کند.

- ورود Google و اتصال امن روش‌های ورود به همان حساب؛ اصلاح کنترل نشست، محدودیت حساب و سیاست احراز هویت مدیران.
- بهبود هدر، داشبورد حساب، سفارش‌ها، فاکتورها و رابط مدیریت.
- تشخیص قطع Redis در زمان اجرا، fallback، هشدار و اتصال مجدد پس از بازیابی.
- اصلاح شمارش رسانه و دسته‌بندی و رفتار retry در صف موجود.
- حذف خواندن تکراری برخی تنظیمات در همان درخواست و بارگذاری CSS اختصاصی Admin فقط در پنل.

## آپدیت و مهاجرت

فایل **mobocom-1.7.16.mbrelease** را در **پنل سرور ← به‌روزرسانی امن** بارگذاری کنید، یا `sudo mobocom update 1.7.16` را اجرا کنید. همان ناشر قبلی و پشتیبان‌گیری اجباری لازم‌اند. ZIP سورس فایل آپدیت نیست. این بستهٔ امضاشدهٔ سورس، روی سرور Linux خودتان بیلد می‌شود؛ بیلد GitHub، نیاز حافظه و دیسک سرور نصب‌شده را حذف نمی‌کند. RAM آزاد، swap و `BUILD_MEMORY_MB` را بررسی کنید.

مهاجرت تازهٔ `20270301120000_google_login` ستون‌های `googleId`، `googleEmail` و `googleLinkedAt` و ایندکس یکتای شناسهٔ Google را اضافه می‌کند؛ دادهٔ موجود حذف نمی‌شود. فعال‌سازی Google نیازمند تنظیم client و redirect صحیح مالک است. **Guest Cache را خاموش نگه دارید.**

## شواهد و محدودیت‌ها

در اعتبارسنجی پیش از شماره‌گذاری انتشار، tree یکپارچه با main مبنا یکسان بود: ۱۱۰۹ تست، ۲۰۲ سناریوی PostgreSQL، Redis واقعی و قطع/بازیابی، بیلد production و Smoke امنیت/حساب/فروشگاه/فاکتور/Admin اجرا شدند. نتیجهٔ جداگانهٔ بررسی‌ها و بیلد GitHub برای commit دقیق انتشار در PR انتشار و توضیح Release ثبت می‌شود؛ این شواهد، تأیید محیط Production نیست.

هنگام قطعی Redis، محدودیت fallback در هر پردازش جداست؛ در N نمونه ممکن است تا N برابر allowance پذیرفته شود و شمارنده‌های محلی به Redis بازیابی‌شده منتقل نمی‌شوند. چرخهٔ واقعی Google OAuth و تحویل واقعی Telegram اجرا نشده‌اند. عیب قبلی کنتراست اتوماسیون تاریک جداگانه در [Issue #426](https://github.com/WebNetData/MoboComCMS/issues/426) ثبت شده است.

## بررسی و بازگشت

پس از آپدیت نسخهٔ پنل، `/api/health/ready`، ورود و تغییر رمز، پروفایل، فروشگاه، فاکتور و پنل مدیریت را بررسی کنید. اتصال و هشدار Redis و تنظیمات Google/Telegram به محیط مقصد وابسته‌اند. بکاپ قبل از نصب را حذف یا دور نزنید. بازگشت کد، ستون‌های افزایشی و داده‌ها را نگه می‌دارد؛ بازگردانی دیتابیس تصمیم جداگانهٔ مالک است. هیچ Deployment توسط سازندهٔ این انتشار انجام نمی‌شود.
