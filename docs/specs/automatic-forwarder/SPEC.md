# Automatic external links

Goal: the existing Forwarder optionally applies to every public HTML anchor, including old rich text, builder/theme links and dynamically inserted links. Turning it off restores direct destinations without rewriting stored content.

Owner/risk: Forwarder + existing Settings/extension state, R3 (public URLs and remote input). Existing evidence: `forwarder.v1`, `/admin/forwarder`, raw and saved forwarding/countdown already exist; automatic application is missing. No new model, migration, identity, permission, editor block, theme or plugin registry.

Change envelope: add a default-off `autoExternalLinks` switch to the existing form and typed setting. Only the existing `forwarder.manage`/`settings.manage` guard can save it; retain Origin policy. Sparse transactional Settings CAS preserves independent changes and unknown fields; strict audit commits with the setting. Invalid input/corrupt saved state cannot overwrite settings. Never rewrite articles/documents or create ShortLink rows for automatic links.

Public contract: `GET /api/forwarder/policy` returns only `{ enabled, siteHost }`, no ad code/private settings, with no-store caching. The site shell applies the policy after hydration to HTTP(S) anchors, preserving query/fragment, rel, target and download attributes. Internal paths, current/configured host, fragment/mail/phone/non-web links, editable controls, Admin and the forwarder page itself are excluded. Dynamic/changed anchors and keyboard/new-tab interactions use the same policy. No fetch to destination. JavaScript-disabled documents retain original direct links.

Automatic URLs are `/forwarder?auto=1&url=<encoded original URL>`. The server revalidates the target and blocked hosts. Automatic forwarding is independent of manually allowed raw URLs. If its switch, the Forwarder switch or extension is off, previously generated automatic URLs temporarily redirect directly; manually created short links keep their existing semantics. The browser refreshes policy on route/focus, after an Admin save and every 30 seconds while visible; failed refresh restores direct links. Public rendering is visually unchanged. Admin adds a native labeled checkbox and concise RTL help using current primitives/tokens; loading/error/save feedback stays with the existing form.

Proof: extend `forwarder.test.cjs` with classification, encoding, disabled and hostile URL cases; add `automatic-forwarder.connected.cjs` to the PG runner for real guard/Origin, sparse concurrent first-row saves, corruption and strict audit rollback, runtime disable and untouched stored content; browser checks actual Admin save/reload, old/new/dynamic anchors, keyboard/new tab, off restoration, stale URL bypass, public/Admin/forwarder exclusions, four 1440/390 light/dark states and scoped axe. Deliberately break automatic disable and CAS preservation and require their checks to fail. Run native relevant type/architecture/source/security checks and affected React Doctor. Owner merges/deploys; rollback is switch/extension off or reverting this slice.
