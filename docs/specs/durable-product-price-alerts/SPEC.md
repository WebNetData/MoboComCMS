# Durable product price-drop delivery

## Audit evidence
`contentChanged` already compares base-product priceMinor and calls `notifyFollowers`; `ItemFavorite.notify` is the existing opt-in and central Inbox owns delivery preferences and channel jobs. Do not add another subscriber/Identity/notification table. Real gaps: the hook is fire-and-forget, several existing writers never call it, currency is not compared, reusing the same amount can suppress a later legitimate drop, and follower delivery stops at 5000 while swallowing failures. StockAlert already exists and must be preserved.

## Vertical slice
- Reuse the newly transactional public-price capture to persist one existing BackgroundJob for an actual base-price drop in the same transaction as its ProductPricePoint. Compare before/after approved active regular prices in the same currency. Baselines, private transitions, increases, metadata/VIP/list edits and currency conversion do not trigger a drop. No external side effects inside price transactions.
- Register a price-drop kind in the existing operations queue. A Catalog worker validates its price observation/owner, current Store/publication/currency/offer state and the existing user's active subscription before creating FOLLOWED_UPDATE through central Inbox. Keep canonical UserId and central SMS/email/push preferences.
- Deliver in bounded user-ID pages, with a durable continuation/checkpoint and point-specific dedupe keys. Inbox success followed by an interrupted worker is safe to retry; failures propagate so the shared queue retries instead of claiming success.
- Add a legitimate Store Admin toggle (default true, preserving the existing enabled follow-notice behavior and omitted keys). Disable suppresses new delivery while preserving observations/subscriptions.
- Remove only the superseded product price branch in contentChanged after the durable path is integrated; other content/search/announcement/restock behavior remains.
- Preserve existing UI/API/favorite semantics. Variant-specific threshold subscriptions are a separate audited extension; this slice hardens the existing base-product follow behavior and does not claim those complete.
