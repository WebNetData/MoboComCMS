# Visual site studio

Owner request2026-11-07: a fullscreen Elementor-class visual designer for pages,
themes, header/footer, individual/global content and products, member dashboard,
modern configurable effects and optional AI assistance. Extend the existing
builder; do not import Elementor or create a second document/theme system.

## Evidence and change envelope

Site owns v2 BuilderDoc, advanced styles/effects, global kit, live module feeds,
saved templates, theme index/conditions, per-entry layouts and revision history.
The editor already has drag/drop, desktop/tablet/mobile previews, undo/redo and
private draft preview. Public BuilderRenderer and owner-provided slots are the
canonical renderer. Article templates were retired on2026-10-30; old records
must remain inactive. Dashboard currently composes canonical authenticated
overview data in its own client view. AI already owns purpose routing, encrypted
personal Admin connections and bounded generation.

RiskR4; Site/Theme owns presentation, Account and content modules keep their real
queries, authorization, private/money states and actions. No new identity,
editor document, settings authority, payment path or executable theme registry.
No automatic public redesign, module activation, production deployment or purge.

## Implementation slices

1. Finish the existing fullscreen workspace: focused toolbar, reliable same-origin
   server-rendered live refresh without navigating the frame on every keystroke,
   explicit preview/save failure states, current live-document revision claims,
   and optional AI design proposals applied only to the unsaved local document.
2. Extend the existing theme registry with typed surface templates and closed
   current-entry/part bindings. Support member-home composition from the actual
   owner-rendered cards; specialist entry adapters retain their gated owner
   content. Specific-item conditions outrank section/global rules. Article layout
   authoring returns only for newly created generation-marked templates: never
   reactivate archived layouts or obsolete per-article settings implicitly.
3. Provide a coherent design entry point and presets using ordinary existing
   blocks/styles, and connect template/rule/individual entry workflows. Header,
   footer, products and page builders stay the same owners and URLs. Defaults
   remain unchanged until explicit publish; off/unpublish falls back safely.

## Authorization and contracts

Private Admin routes use canonical `requirePerm`, write Origin, strict limits
when generating AI, module guards, typed bounded input and strict audit for new
writes. Existing per-section permissions remain; global/member presentation
requires settings.manage. Member slots fetch only the current authenticated
member's canonical overview; private values are never stored in a template,
cached publicly or sent to AI. Public entry adapters run after access gates.

Theme metadata, BuilderDoc and new bindings remain backward compatible; Settings
value claims and existing ContentRevision retain prior designs. Preview drafts
never become public. Conflicts retain the local work and require reload/review.
AI uses its own purpose inheriting Admin routing, on explicit request only,
without server commands or generated JavaScript, secret/financial/catalogue
snapshots or silent publication. Reject stale proposal application when the
source document changed. Client preview messages validate origin/window/page.

Focused existing builder/theme/AI tests plus registered native PostgreSQL checks
for revision conflicts/audit rollback, new-template archive separation, specific
rule selection, module-off fallback, current-member isolation and AI permission/
schema/stale proposal denials. Detect deliberate faults in critical claims.
Actual browser: baseline, create/edit/select/drag/style/undo, live preview,
save/reload/conflict, header/footer/post/product/surface rules, independent member
views, optional recorded AI proposal/apply/cancel and four1440/390 light/dark
loaded views with scoped axe. Relevant type/source/architecture/schema/security,
Doctor and exact tested source hashes. Broader build once when practical, no
full release stack after every edit or live paid provider. Report implemented
coverage and gaps honestly; do not claim compatibility with every Elementor
third-party add-on, arbitrary root code, or unexecuted host/provider checks.
