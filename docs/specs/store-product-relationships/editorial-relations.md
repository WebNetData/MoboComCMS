# Editorial product relationships

## Evidence and outcome
CMS product writers already own `cms.products`, validated product input, transaction-scoped variant writes and price-history locks. AdminCrud exposes editor extra keys/compositions; the shared Content registry owns public item resolution/search. Store category/brand recommendations and the related-products tab already exist. Add directed editorial RELATED, COMPLEMENTARY and COMPATIBLE references to those owners; no duplicate Product, search, recommendation, cart or identity system.

## Data / authorization / compatibility
Add ProductRelationship with source/target Product FKs, kind, position and unique source/kind/target. Positive source/target, no self links, recognized kinds and bounded ordered unique input (12 per kind,36 total). New targets must be public and Store enabled; existing withdrawn targets may remain saved without exposing their names publicly. Source/target deletion cascades only their dependent relationships; module/config disable preserves rows. Existing clients that omit relationships preserve them. CMS create/update saves links atomically with product/variants/price history; invalid selections roll back the whole change. Catalog picker uses shared registry and existing cms.products permission, filters self, bounded search and selected refs. No seller authorization widening.

## Public experience / Admin configuration
Existing Store merchandising Admin controls rollout. Default false preserves current layout; pause returns no editorial cards and retains records. RELATED editorial IDs rank first in both existing related rail and related tab, then their current automatic fallbacks fill remaining slots, without duplicates. COMPLEMENTARY/COMPATIBLE optional tabs reuse existing product-tab/card styling and explicit directional wording; compatibility is an editorial assertion, never inferred from co-purchase/category/brand. Only current approved/active targets are returned; private source/API remains404. No protected surface redesign.

## Migration / gates
Incremental PostgreSQL table/index/FK/check migration; matching SQLite/PostgreSQL Prisma models. Snapshot local DB first, validate schemas/parity and actual migration; local snapshot is not a verified production backup/restore. Domain/transaction/picker/publication/rollout/fallback ordering tests; real PG/CMS API atomic rollback/old-client preservation/permissions/self/hidden/deletion checks; real editor/product RTL light/dark responsive browser flow. Public additive tabs have scoped OpenAPI/Hurl/Spectral contracts. TypeScript/source/security/architecture/cruiser, relevant suites, clean committed-source build and CI before merge.
