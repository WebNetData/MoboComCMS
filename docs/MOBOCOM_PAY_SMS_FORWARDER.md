# تنظیم SMS Forwarder برای تأیید کارت‌به‌کارت

این تنظیمات فقط متعلق به مدیریت موبوکام و گوشی دریافت‌کنندهٔ پیامک کارت‌های
موبوکام است. پذیرنده از کارت‌های پلتفرم استفاده می‌کند و توکن پیامک یا دسترسی
حساب بله را دریافت نمی‌کند. تنظیم روش تأیید خودکار نیز فقط مدیریتی است.

1. در **مدیریت ← موبوکام‌پی ← تنظیمات درگاه ← منابع پیامک بانکی**، حساب بانکی
   اختصاصی فعال را انتخاب و منبعی با قالب **SMS Forwarder سه‌فیلدی** بسازید.
2. شناسهٔ بانک مثل `bankmeli` را با قالب پیامکی و واحد صحیح ریال/تومان ثبت کنید.
   شناسهٔ بانک یک کد داخلی منبع است؛ با فرستندهٔ واقعی پیامک فرق دارد.
3. برنامهٔ [SMS Forwarder](https://play.google.com/store/apps/details?id=com.frzinapps.smsforward)
   را روی گوشی صاحب کارت تنظیم کنید. نام دقیق کنترل‌ها ممکن است با نسخهٔ برنامه
   فرق داشته باشد؛ مقصد باید یک درخواست HTTP با مشخصات زیر باشد.

| فیلد | مقدار |
| --- | --- |
| Method | `POST` |
| URL | نشانی کامل HTTPS همان منبع که پنل نمایش می‌دهد |
| Header | `Content-Type: application/json` |
| بدنه | JSON زیر، با کد بانک و توکن همان منبع |
| Authorization/Bearer | برای قالب سه‌فیلدی لازم نیست |

شکل نشانی؛ `SOURCE_ID` را حدس نزنید، نشانی کامل را از پنل کپی کنید:

```text
https://YOUR-DOMAIN/api/payment/mobocom-pay/sms-forwarder/SOURCE_ID
```

```json
{
  "sms": "{msg}",
  "bank": "bankmeli",
  "token": "توکن تولیدشده برای همین منبع"
}
```

`{msg}` عیناً می‌ماند تا برنامه متن پیامک تازه را جایگزین کند. توکن فقط هنگام
ساخت منبع نمایش داده می‌شود؛ در URL قرار نگیرد. پس از بازخوانی صفحه، راهنما فقط
جای‌نگهدار توکن را نشان می‌دهد. اگر توکن را از دست داده‌اید، منبع قبلی را متوقف
و منبع جدید بسازید؛ بازیابی توکن قبلی از پنل وجود ندارد.

فیلتر گوشی را روی فرستندهٔ دقیق بانک بگذارید؛ پیام‌های قدیمی، دستی یا فورواردشده
را برای آزمون مالی بازپخش نکنید. دسترسی‌های لازم برنامه و محدودیت باتری را طبق
نسخهٔ نصب‌شده بررسی کنید. نخست تنظیم منبع را با قالب واقعی بانک تطبیق دهید؛ سپس
منبع، درگاه کارت‌به‌کارت و مجوز خودکار پذیرنده/پایانه را از مدیریت فعال کنید.

قالب پیشرفتهٔ `EXTENDED_V1` مسیر `/sms/SOURCE_ID`، سربرگ Bearer و پیام دارای زمان/
شناسهٔ مستقل دارد؛ با JSON سه‌فیلدی مخلوط نشود. قالب سه‌فیلدی زمان اصلی پیامک را
نمی‌فرستد؛ برای خرید USDT با نرخ قفل‌شده به مدرک زمان‌دار بله یا قالب پیشرفته نیاز
است و پیام فاقد آن خودکار مبنای تأیید آن خرید نمی‌شود.

در **پایش دریافت‌ها** و **میز مغایرت‌ها**، دریافت پیام را از ثبت پرداخت تشخیص دهید.
هر پیام دریافتی الزاماً پرداخت نیست. تأیید دستی، پیامک و بله یک فاکتور را یک بار
ثبت می‌کنند؛ کارمزد به اعتبار مشتری/پذیرنده اضافه نمی‌شود. اتصال واقعی گوشی، بانک
و سرور باید با یک فاکتور آزمایشی معتبر راه‌اندازی و بررسی شود.
