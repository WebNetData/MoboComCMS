# راهنمای اتصال‌های موبوکام کلاد

مدیریت اتصال‌ها در «موبوکام کلاد ← سامانه‌های متصل» است و مجوز
hosting.manage می‌خواهد. رمزها رمزگذاری می‌شوند و پس از ذخیره دوباره نمایش داده
نمی‌شوند. ثبت اطلاعات، تأیید ورود و اجرای عملیات سرویس سه وضعیت متفاوت‌اند.

| سامانه | آزمون پیاده‌شده | ساخت یا ثبت خودکار در این مرحله |
| --- | --- | --- |
| cPanel / WHM | ورود با رمز یا توکن WHM، خواندن بسته‌های مجاز نمایندگی | فعال نیست |
| Proxmox VE | احراز توکن و خواندن مجوزهای مؤثر همان حساب | فعال نیست |
| Hetzner Cloud | احراز توکن و خواندن مکان‌های API ثابت پروژه | فعال نیست |
| Joker.com | ورود DMAPI با API Key یا رمز، پایان نشست | ثبت/تمدید خودکار فعال نیست |
| ایرنیک | با حساب معمولی nic.ir، اتصال API تأیید نشده است | سفارش و تمدید با کارشناس |
| سایر گزینه‌های قدیمی فهرست | آداپتور آماده نیست؛ در پنل مشخص است | تحویل با کارشناس |

این جدول وضعیت کد را نشان می‌دهد. موفقیت آزمون یک حساب واقعی به کلید، مجوز،
شبکه و سیاست میزبان همان حساب وابسته است.

## اتصال نمایندگی cPanel / WHM

1. اتصال تازه و نوع cPanel / WHM را انتخاب کنید.
2. نشانی مستقیم WHM مانند https://whm.example.com:2087 را وارد کنید. مسیر
   cpsess یا login، نام کاربری/رمز در URL و پورت cPanel یعنی ۲۰۸۳ مناسب نیستند.
   نشانی HTTPS سرویس WHM روی پورت ۴۴۳ هم پذیرفته می‌شود.
3. نام کاربری خود WHM، حساب root یا نمایندهٔ مجاز را وارد کنید.
4. اگر رمز ورود WHM دارید، «رمز ورود WHM» را انتخاب و رمز را در فیلد خودش وارد
   کنید. اگر توکن دارید، «API Token حساب WHM» را انتخاب کنید. توکن ساخته‌شده
   داخل cPanel با توکن WHM یکی نیست.
5. ذخیره کنید و «بررسی اتصال» را بزنید. آزمون فقط خواندنی است: نسخهٔ WHM را با
   پاسخ موفق API بررسی و سپس بسته‌های قابل دسترس همان نمایندگی را می‌خواند.
   هیچ حساب هاستی ساخته یا حذف نمی‌کند.

برای توکن، در WHM به Manage API Tokens بروید. دسترسی نمایندگی به این قسمت
و ACLهای توکن را میزبان اصلی تعیین می‌کند. برای نمایش بسته‌ها، مجوز
List Packages لازم است. نداشتن این مجوز پس از ورود معتبر، جداگانه گزارش
می‌شود و به معنی اشتباه بودن رمز نیست.
[راهنمای رسمی توکن WHM](https://api.docs.cpanel.net/whm/tokens) و
[مجوزهای نماینده](https://docs.cpanel.net/whm/resellers/edit-reseller-nameservers-and-privileges/).

پاسخ ۴۰۱/۴۰۳ یا invalid_login را با سبز کردن وضعیت نادیده نگیرید. ورود واقعی
به همان WHM را خصوصی بررسی کنید؛ نام کاربری و نقش نمایندگی، رمز/توکن، IP
مجاز، cPHulk، سیاست Basic Authentication و ورود دومرحله‌ای را از میزبان
پیگیری کنید. توکن مجاز WHM ممکن است برای اتصال برنامه لازم باشد. در صورت
استفاده از توکن، آن را فقط در پنل خصوصی موبوکام وارد کنید.

کد بسته‌های خوانده‌شده برای تنظیم پلن قابل استفاده است؛ وجود کد بسته به‌تنهایی
ساخت خودکار را فعال نمی‌کند. تحویل فعلی تا آماده شدن آداپتور عملیات با کارشناس
انجام می‌شود.

## Joker.com

نوع Joker.com DMAPI را انتخاب کنید؛ مقصد از کد روی dmapi.joker.com ثابت است.
برای API Key، کلید DMAPI را از حساب خود بگیرید و در فیلد کلید وارد کنید.
برای ورود با رمز، روش «رمز ورود Joker» و ایمیل حساب را انتخاب کنید.
آزمون با POST فرم‌کدگذاری‌شده انجام می‌شود؛ رمز، کلید و شناسهٔ نشست در URL
قرار نمی‌گیرند و نشست ایجادشده پس از آزمون بسته می‌شود.

دسترسی کامل DMAPI به حساب نمایندگی و سطح دسترسی کلید وابسته است. ورود موفق،
مجوز پرداخت هزینهٔ دامنه یا تکمیل ثبت نیست. ثبت و تمدید Joker علاوه بر ورود،
به اطلاعات صحیح صاحب امتیاز، شناسه‌های تماس و نیم‌سرورها، بودجهٔ مجاز، ثبت
پایدار شناسهٔ پردازش و بازیابی نتیجهٔ درخواست‌های غیرهم‌زمان نیاز دارد. این
عملیات در این مرحله خودکار نشده‌اند.
[قرارداد رسمی DMAPI](https://dmapi.joker.com/docs/DMAPI-ext.txt).

## حساب معمولی ایرنیک

رمز ورود معمولی nic.ir را در فیلد «API» وارد نکنید. برای حساب معمولیِ فعلی،
ثبت و تمدید از مسیر موجود کارشناس انجام می‌شود و دسترسی API فرض نمی‌شود.
ایجاد اتصال API تازهٔ ایرنیک تا دریافت و بررسی قرارداد معتبر نمایندگی بسته است؛
داده‌های قبلی، شناسه‌های ایرنیک مشتریان و سفارش‌های موجود حفظ می‌شوند.

## سرورهای Proxmox و Hetzner

Proxmox: نشانی HTTPS مدیریت روی پورت ۸۰۰۶ یا ۴۴۳، شناسهٔ کامل
user@realm!tokenid و secret همان توکن را وارد کنید. آزمون، API مجوزهای حساب
را می‌خواند؛ صفحهٔ عمومی نسخه، معیار احراز هویت نیست. مجوز خالی یعنی ورود
تأیید شده ولی مجوز عملیاتی قابل اتکایی برای ساخت ماشین نشان داده نشده است.

Hetzner: فقط توکن پروژه وارد می‌شود؛ مقصد API ثابت است. آزمون خواندن مکان‌ها،
مجوز ساخت یا حذف سرور را اثبات نمی‌کند.

## شبکه، TLS و تغییر اطلاعات اتصال

TLS باید معتبر و با نام میزبان منطبق باشد. بررسی گواهی غیرفعال نمی‌شود و
درخواستِ حاوی کلید، تغییر مسیر را دنبال نمی‌کند. پاسخ‌ها محدودیت حجم و مهلت
دارند. برای سرور با گواهی خصوصی، زنجیرهٔ CA معتبر را از مسیر مورد اعتماد
مدیریت سرور تنظیم کنید؛ گزینهٔ «نادیده گرفتن SSL» وجود ندارد.

سرورهای خصوصی به‌صورت پیش‌فرض مسدودند. مدیر استقرار می‌تواند فقط نام دقیق
میزبان‌های داخلیِ مجاز را در محیط سرور تعیین و سرویس را بازراه‌اندازی کند:

    HOSTING_PRIVATE_API_HOSTS=pve.internal.example,whm.internal.example

نام wildcard پذیرفته نمی‌شود. مقصدهای loopback، link-local و سرویس metadata
حتی با این تنظیم مجاز نمی‌شوند. مشتری نمی‌تواند میزبان این درخواست‌ها را
انتخاب کند؛ این اختیار فقط در مدیریت اتصال‌های پلتفرم است.

هنگام ویرایش، خالی گذاشتن رمز فقط برای همان اتصال آن را حفظ می‌کند. تغییر
نشانی، حساب، نوع سامانه یا روش ورود، وارد کردن دوبارهٔ رمز/توکن را لازم دارد.
وضعیت آزمون قبلی پاک می‌شود؛ نتیجهٔ آزمونی که هنگام ویرایش در حال اجرا بوده،
نمی‌تواند تنظیمات تازه را «متصل» نشان دهد.
