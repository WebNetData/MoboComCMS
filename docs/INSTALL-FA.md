# نصب موبوکام

این راهنما ساده‌ترین راه نصب است: یک سرور اوبونتوی تازه، یک دامنه و یک دستور. برای کار با آن لازم نیست برنامه‌نویس باشید.

| شرایط شما | راه مناسب |
| --- | --- |
| سرور مجازی اوبونتو دارید | **همین راهنما** (پیشنهادی) |
| با Coolify کار می‌کنید | [راهنمای Coolify](DEPLOY-COOLIFY.md) |
| فقط هاست cPanel یا DirectAdmin دارید | [بخش هاست](DEPLOY-VPS-HOST-FA.md#بخش-ب--هاست-cpanel--directadmin-با-setup-nodejs-app) |
| می‌خواهید هر قدم را خودتان دستی انجام دهید | [نصب دستی روی اوبونتو](DEPLOY-UBUNTU.md) |

بعد از نصب، برای آپدیت این راهنما را بخوانید: [آپدیت بدون از دست رفتن اطلاعات](UPGRADE-FA.md).

## پیش از شروع

- **سرور:** Ubuntu 22.04 یا 24.04، حداقل ۲ هسته، ۴ گیگ رم و ۴۰ گیگ دیسک. پیشنهاد ما ۴ هسته و ۸ گیگ رم است.
- **دامنه:** رکورد A دامنه باید به IP سرور اشاره کند. اگر `www` هم می‌خواهید، برای آن هم رکورد بسازید.
- **دسترسی:** ورود با SSH با کاربر `root` یا کاربری که `sudo` دارد.
- **حساب GitHub:** چون مخزن خصوصی است، باید بتوانید در تنظیمات مخزن یک کلید اضافه کنید.

## نصب در چهار قدم

### قدم ۱: فایل نصب را روی سرور بیاورید

1. در GitHub فایل [`deploy/ubuntu/install.sh`](../deploy/ubuntu/install.sh) را باز کنید و روی **Raw** بزنید.
2. نشانی صفحه‌ای که باز می‌شود را کپی کنید. این نشانی یک کد موقت دارد و چند دقیقه معتبر است.
3. روی سرور این دستور را اجرا کنید و نشانی را داخل کوتیشن بگذارید:

```bash
curl -fsSL 'نشانی-کپی‌شده' -o install.sh
```

### قدم ۲: نصب را اجرا کنید

```bash
sudo bash install.sh --domain example.com --email you@example.com
```

به‌جای `example.com` دامنهٔ خودتان و به‌جای ایمیل، ایمیل خودتان را بگذارید. ایمیل فقط برای گواهی SSL استفاده می‌شود.

این کارها خودکار انجام می‌شود:

- نصب Node.js 22، PostgreSQL 17، Redis و Nginx
- ساخت swap در صورت کمبود رم و تنظیم دیواره‌آتش
- ساخت کاربر سرویس، دیتابیس و همهٔ کلیدهای رمزگذاری
- دریافت کد و ساخت برنامه
- راه‌اندازی سرویس، پشتیبان‌گیری روزانه و گواهی SSL

نصب بسته به سرور و شبکه طول می‌کشد. اتصال SSH را نبندید. اگر اتصال قطع شد، ابتدا مطمئن شوید نصب قبلی تمام شده است؛ سپس همان دستور را دوباره اجرا کنید. فایل تنظیمات، دیتابیس موجود، کد موجود و فایل‌های ذخیره‌شده حفظ می‌شوند؛ تنظیمات سرویس ممکن است دوباره نصب شوند. روی نصب دارای تنظیمات سفارشی از راهنمای دستی استفاده کنید.

### قدم ۳: کلید GitHub را اضافه کنید

چون مخزن خصوصی است، نصب در این مرحله یک خط که با `ssh-ed25519` شروع می‌شود نشان می‌دهد و منتظر می‌ماند.

1. در GitHub به **Settings ← Deploy keys ← Add deploy key** بروید.
2. آن خط را بچسبانید.
3. گزینهٔ **Allow write access** را روشن نکنید.
4. به ترمینال برگردید و Enter بزنید.

این کلید فقط اجازهٔ خواندن کد را می‌دهد و بعداً هم برای آپدیت استفاده می‌شود.

### قدم ۴: نصب را در مرورگر تمام کنید

در پایان، نصب دو چیز را نشان می‌دهد: نشانی `https://example.com/install` و یک **کد نصب**.

1. نشانی را باز کنید و کد را وارد کنید.
2. نام سایت، حساب مدیر اصلی و بخش‌هایی را که می‌خواهید انتخاب کنید.
3. بعد از ساخت مدیر اصلی، صفحهٔ نصب برای همیشه بسته می‌شود و به پنل `/admin` می‌روید.

## یک کار مهم بعد از نصب

از فایل تنظیمات یک نسخه جایی **بیرون از سرور** نگه دارید، مثلاً در مدیر رمز:

```bash
sudo cat /etc/mobocom/mobocom.env
```

کلیدهای رمزگذاری در این فایل هستند. بدون آن‌ها، اطلاعات رمزشده در پشتیبان دیتابیس قابل خواندن نیست. این فایل را در Git، تیکت یا پیام‌رسان نگذارید و مقدار `PANEL_CREDENTIAL_KEY` را هرگز عوض نکنید.

## بررسی نصب

```bash
sudo mobocom status
```

خروجی باید `service: active` و `site: healthy` را نشان دهد. سپس در مرورگر این موارد را امتحان کنید:

- ورود به `/admin`
- ذخیره و نمایش یک مطلب
- آپلود یک تصویر
- پیش از فروش واقعی، یک خرید آزمایشی با درگاه خودتان

## گزینه‌های نصب

| گزینه | کاربرد |
| --- | --- |
| `--domain` | دامنهٔ سایت. اگر ندهید، نصب می‌پرسد. |
| `--email` | ایمیل گواهی SSL. اگر ندهید، نصب می‌پرسد. |
| `--no-ssl` | گواهی نمی‌گیرد. پیش از واردکردن کد نصب و ورود کاربران، HTTPS را روی پراکسی یا سرور تأمین کنید. |
| `--no-firewall` | به دیواره‌آتش دست نمی‌زند. |
| `--branch` | شاخهٔ کد. پیش‌فرض `main` است. |
| `--repo` | مخزن مورد اعتماد روی GitHub، با HTTPS یا SSH؛ کد این مخزن روی سرور اجرا می‌شود. |

اگر گواهی SSL در نصب گرفته نشد، سایت نصب شده است و فقط HTTPS مانده. بعد از درست‌کردن DNS این دستور را اجرا کنید:

```bash
sudo certbot --nginx -d example.com -d www.example.com --redirect
```

با Cloudflare، حالت SSL را روی **Full (strict)** بگذارید و برای ارتباط Cloudflare تا سرور هم گواهی معتبر نصب کنید. حالت Flexible کافی نیست.

نصب خودکار از مسیر `/opt/mobocom/app` و کاربر `mobocom` استفاده می‌کند. کلید میزبان SSH گیت‌هاب با [کلید رسمی GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints) تطبیق داده شده است؛ اگر کلید رسمی عوض شد، آن را پس از بررسی منبع رسمی به‌روز کنید. فایل‌های دارای دسترسی ریشه از یک دریافت جداگانهٔ مخزن مورد اعتماد در مسیر خصوصی ریشه نصب می‌شوند؛ کد قابل‌ویرایش کاربر سایت به‌عنوان ریشه اجرا نمی‌شود.

تست‌های محلی بکاپ، بازیابی و آپدیت در [گزارش فنی](agent/handoffs/HOST_INSTALL_UPGRADE.md) ثبت شده‌اند. نصب کامل روی VPS تازه، systemd واقعی، صدور و تمدید گواهی و درگاه پرداخت باید روی زیرساخت مقصد هم بررسی شوند.

## اگر مشکلی پیش آمد

| پیام یا نشانه | معنی | راه‌حل |
| --- | --- | --- |
| `this installer supports Ubuntu 22.04 and 24.04` | نسخهٔ سیستم‌عامل پشتیبانی نمی‌شود. | سرور را با یکی از این دو نسخه نصب کنید یا از [Coolify](DEPLOY-COOLIFY.md) استفاده کنید. |
| `at least 15 GB is needed` | دیسک کافی نیست. | فضای دیسک را بیشتر کنید. |
| `the database user already exists but ... is missing` | فایل تنظیمات نیست ولی دیتابیس هست. | نسخهٔ ذخیره‌شدهٔ `mobocom.env` را در `/etc/mobocom/` بگذارید و نصب را دوباره اجرا کنید. نصب عمداً دیتابیس را دست نمی‌زند. |
| `the site did not start` | برنامه بالا نیامد. | `sudo journalctl -u mobocom -n 80 --no-pager` را ببینید. |
| `[preflight]` در لاگ | یکی از تنظیمات درست نیست. | پیام همان خط را بخوانید و `/etc/mobocom/mobocom.env` را اصلاح کنید. |
| `JavaScript heap out of memory` | رم برای ساخت کافی نیست. | swap را بیشتر کنید و نصب را دوباره اجرا کنید. |
| `502 Bad Gateway` | برنامه هنوز بالا نیامده یا متوقف شده. | چند دقیقه صبر کنید و `sudo mobocom status` را ببینید. |

برای پنل سرور، دامنه‌ها و گواهی‌ها از داخل مدیریت، [نصب تحت وب و پنل سرور](WEB_SETUP_AND_SERVER.md) را بخوانید.
