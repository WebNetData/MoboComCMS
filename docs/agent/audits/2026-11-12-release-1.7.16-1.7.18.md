# Engineering reconciliation for 1.7.16–1.7.18

Reviewed 2026-11-12 against owner-merged `origin/main` `1cd2406e`, including PR446. The older `autonomous-foundation` checkout is at `cde4ec7b` and predates these releases. Continue this correction in `.mobocom/repair-counter-audit`, branch `fix/repair-counter-audit-2026-11-12`.

## Findings

- **PARTIAL documentation**. Release notes and several decisions already describe the merged work. The map, capability ledger, domain matrix and form-builder spec omit much of the continuation. This reconciliation connects them to the existing implementation.
- **WEAK_UX counter entry**. PR445 added `/admin/forms/counter?form=<id>`, but its sole entry was inside one form's Answers tab. The all-forms queue hides that entry and the counter cannot choose a form. The follow-up makes the entry available in the Forms header and unpaid service cards and adds an authorized form picker.
- **REGRESSED counter submit state**. Browser inspection found that the staff submit handler skips the public human check while the shared submit button still waits for it. Counter mode now omits the public widget and excludes its readiness from the disabled condition. The existing public submission gate remains covered by the regression check in `scripts/forms.test.cjs`.
- **WEAK_UX handler deep links**. Loading the form list forced handler-only accounts into the all-forms queue even with a valid `?form=<id>` link. Explicit authorized form selection now retains its context, including the intake header link and the receipt's return link.
- Release preparation records are historical. Git proves the metadata PRs were merged. Publication, signatures, real-provider operation and deployment require their own receipts.
