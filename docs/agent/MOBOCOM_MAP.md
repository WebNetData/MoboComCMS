## Core
- **Stack:** Next.js 15 app router in `src/app`, domain code in `src/modules/<module>/{domain,server}`, shared infrastructure in `src/platform`, UI in `src/components`. Prisma with two schemas kept in parity: `prisma/schema.postgresql.prisma` (production, migrations in `prisma/migrations`) and `prisma/schema.prisma` (SQLite, no migration runner).
- **Module registry:** one manifest per plugin, `src/plugins/<id>/manifest.json` (id, `requires`, permissions, admin menu). `npm run extensions:generate` writes `src/extensions/generated/catalog.ts`. Stored and effective state (a module is off when something it requires is off): `src/extensions/server/state.ts`. Guards: `requireModule(id)` for pages, `moduleGuard(id)` / `whenModuleOn(id, handler)` for APIs, `isModuleEnabled(id)` for composing — all in `src/extensions/server/modules.ts`.
- **Extension state writes:** Existing state owner saves settings/stored enable/dependency reads and legacy mirror in one Serializable transaction with bounded retries. Strict mutation reads preserve invalid storage; each node and public runtime gather state/mirror/legacy in one SQL query. [Write evidence](audits/2026-10-11-extension-state.md), [snapshot/preservation evidence](audits/2026-10-11-extension-state-integrity.md); full recovery/legacy writers/multi-node/lifecycle/rollout remain partial.
- **Repository secret consumers:** `repository/server/http/public.ts` composes the existing module/vendor gate with awaited platform `rateLimitStrict` for machine license actions and release downloads; ordinary discovery/buyer limits retain `rateLimitHit`. [Bounded evidence and Import actor-policy handoff](audits/2026-10-11-repository-secret-limits.md); actual :3000 rollout remains pending.
- **Repository machine owner:** The existing vendor public address delegates human-linked license standing/GLOBAL facts to its own `vendor/access.ts` and canonical Identity. Temporary423 preserves unchanged client/installed state; null userId grants stay unbound and signed REVOKED checks remain narrow invalidation signals. [Contract and evidence](audits/2026-10-11-repository-license-owner.md); broader restrictions/rollout remain partial.
- **Masked file owner:** Existing `downloads/server/mask.ts` carries optional encrypted human linkage from media-link/Music/watch issuers, composes canonical current Identity before clean-cache/upstream, and prevents caching bound responses. Legacy/guest grants retain their original TTL; no inferred owner or new token store. [Runtime and compatibility evidence](audits/2026-10-11-masked-file-authority.md); direct origins/resource/module policy and all-instance rollout are separate boundaries.
- **Global restriction Admin:** Existing Identity restriction transaction, canonical current reader, staff guard and strict audit own `/api/admin/users/:id/restrictions` and the customer overview card. Ordered actor/subject locks, private fifty-row cursor history and independent claimed revocation; no standing/financial/forum reset. [Bounded PG/browser evidence](audits/2026-10-11-global-restriction-admin.md); wider policy and rollout remain partial.
- **Telegram account owner:** Existing Identity telegram-account and notifications webhook compose current GLOBAL/standing before effects; ordered locks/tx readers, bounded uniqueness retry and preserved restriction/license ownership. Private message formatting stays behind the webhook address. [Evidence](audits/2026-10-11-telegram-authority.md); modern profile/URL merge remains a reproduced gap.
- **Telegram merge safety:** Private Identity telegram-account/merge-safety preserves source UserProfile/username/timestamps when no target profile; collisions and unsupported actual User FK/inspected scalar references refuse before effects. [Actual PG/browser/rollback evidence](audits/2026-10-11-telegram-merge-safety.md); broader modern transfer and scalar fencing remain partial.
- **Import execution:** canonical owners are `imports/server/{commands,execution,registry,authority}.ts`, dispatched by `operations/server/queue.ts`; `imports.manage` guards HTTP. Upload creator remains immutable; captured operator/time/direction/generation compose Identity's shared current-user reader, RBAC and two-factor policy. Denied authority pauses, explicit authorized takeover preserves direction/history, claims fence stale grants. [Bounded evidence and rollout barrier](audits/2026-10-11-import-execution-authority.md); safe :3000 rollout remains pending.
- **Settings registry:** `src/modules/settings/server` *(not re-verified)*; module settings through `getModuleSettings(id)`; forum settings in `src/modules/forum/server/community.ts` (`getForumSettings`), normalized by `normalizeForumSettings` in the forum domain.
- **Identity/AuthZ:** one `User`; `role` (`ADMIN` | `CUSTOMER`) and optional `roleId` → `Role.permissions` (comma-separated keys; `*` = everything). Staff without a role is full access. Keys and presets: `src/modules/identity/rbac.ts`. Request guards: `requireUser`, `requireAdmin`, `requirePerm` in `src/modules/identity/server/access.ts`; `adminGuard(req, moduleId, anyOfPermissions)` in `server/admin-guard.ts`. Who may change a staff account: `server/staff-guard.ts`. Section managers: `domain/sections.ts`, `server/section-managers.ts`. Public identity (username, follow, block, privacy): `server/profile.ts`, `domain/profile.ts`.
- **Event/outbox/jobs:** background queue and schedulers under `src/modules/notifications/server` (`jobs-scheduler.ts`) and per-module `server/jobs.ts`; content change events `src/modules/content/server/events.ts` *(not re-verified beyond these names)*.
- **Queue claim integrity:** existing `operations/server/queue.ts` fences terminal writes by RUNNING/lockedAt/attempt and terminal dedupe release by inspected state/key. Actual competing PG runners/retry, three deliberate faults and compiled import consumers verified; [evidence](audits/2026-10-11-queue-lease.md). In-flight effects, follow-up enqueue and human manual-job authority remain separate contracts; quiesce old unfenced workers at rollout.
- **Search/notifications/media:** search `src/modules/search/server/search.ts`; inbox notifications `src/modules/notifications/server/inbox.ts` (`createInboxEvent`), which sections an event belongs to in `notifications/domain/event-modules.ts`; shared media library and its admin API `src/modules/media/server/admin.ts` (per-type `perms`); picture upload `src/modules/site/server/http/admin/media/route.ts`; content item cards for any type `src/modules/content/server/registry.ts` (`itemCard`, `itemCards`).
- **Moderation overview:** `src/modules/moderation/domain/queue.ts` (`QUEUE_SOURCES`), each owner module exports `waitingForModeration(take)`.
- **Audit:** `auditAdmin({ req, actor, action, targetType, targetId, metadata })` in `src/platform/audit/server.ts`.
- **Extension/theme registry:** `src/extensions/{client,sdk,server}`, themes in `src/themes` *(not re-verified)*.
- **Public/mobile API:** `src/modules/public-api/server` *(not re-verified)*.
- **Tests/release commands:**
  - `npx tsc --noEmit -p tsconfig.json`; `npm run arch:check | source:check | schema:check | security:check | i18n:check`.
  - `npm run test:site` — unit suites `scripts/*.test.cjs` (run on Linux: some shell out to `sh`).
  - `npm run test:pg` — connected PostgreSQL checks `scripts/*.connected.cjs`, listed in `scripts/run-pg-checks.cjs` (46 at this revision).
  - `npm run integrity:report` — read-only findings on live data (`docs/INTEGRITY-REPORT.md`).
  - `npm run test:e2e` — Playwright specs in `e2e/tests`; GitHub workflow "Browser tests" runs on pull requests.
  - `npm run check` — the full gate; `npm run build:postgres` — production build; `npm run deploy:migrate` — apply migrations.
- **Local run:** `docker compose -f docker-compose.local.yml up -d` (app 3000, PostgreSQL 127.0.0.1:5435); `scripts/local-dev-start.sh` copies the tree into the container, so restart the app container after each change.
