## Owners and implemented behavior

- **Imports:** `imports/server/edit-protection.ts` composes existing ImportRecord changes JSON with source-specific content fingerprints. New wizard forms default `protectEdits` ON; old saved jobs without the field retain their old behavior. Preview and execution both skip a manually changed item, including supported child relationships. Unknown/rolled-back/different-source baselines conservatively skip. Explicit opt-out still permits update/replace. The owner transaction claims the expected parent version and rechecks content. The baseline is captured inside each writer transaction and returned to the engine; later parent or child edits cannot be mistaken for imported state by a post-commit read. Series episode writes now share the title transaction and revision; remote copies finish before locks, protected media writes use Serializable isolation. No extra provenance table or automatic downloads were introduced.
- **History:** existing ContentRevision and `/admin/history` now include supported media links/seasons/episodes/terms, post categories and product catalogue metadata/relationships. Helpers are `media/server/revision-state.ts`, `site/server/revision-state.ts`, `catalog/server/revision-state.ts`. Old scalar-only snapshots preserve current relationships. Restores preserve link IDs/counters/reports/entitlements and current moderation removals; unused links are hidden. Missing post categories refuse the whole restore. Product restore never rewinds price, stock, financial state, creator or ownership. Product editors link to history. New affected owner saves record revisions in their write transaction.
- **Moderation:** existing `completeOwnerCase`/`completeTrashCase` complete OPEN/CLAIMED cases from comments, product feedback, item/business experiences, Forum approvals/flags, Community reports, copyright decisions and content-trash decisions. Cases remain keyed by exact source/item; repeated decisions retain their first record. Core owner changes and case writes are atomic where their owner already exposes a transaction, including trash restore/delete. `noteCase` no longer writes a note before refusing a decided case. The overview POST requires a valid Origin.
- **Duplicate profiles:** existing CinemaPerson/MusicArtist gain nullable `mergedIntoId` self references, additive migration `20270108120000_people_profile_merges`, listed in the release manifest and both schemas. Existing section managers preview and explicitly confirm a merge using `ProfileMergePanel`. Serializable, version-claimed owner commands and strict audit move/deduplicate credits, track/album references and favorite subscriptions. Destination metadata wins; a manually locked empty portrait stays empty. Source names/slugs/IDs remain aliases, public old URLs return308, imports/filter links resolve the canonical profile, and canonical lists exclude aliases. These are content profiles, never authentication identities. Source rows are retained; no automatic undo.
- **Cinema follow:** `person` extends the existing content vocabulary and ItemFavorite service. Existing inbox/queue services deliver opted-in first-publication notices through `cinema.person-publication`,100 recipients per continuation, with per-user/person/title deduplication and subscription cutoff. - **Player:** existing VideoPlayer composes `player/SubtitleControls.tsx` and `SeparateAudioControls.tsx`. Authorized same-owner tracks retain module/publication/token/paywall/takedown checks. ASS/SSA uses lazy, pinned MIT `assjs@0.1.10`, with bounded raw delivery, plain WebVTT fallback and delay control. ## Limits / next work

- Shared category/artist/album preparation and copied files retain the importer’s existing tracked owner boundaries; failed records can retain preparation for rollback. Protection is conservative around a changed shared album/category state, not a cross-domain all-or-nothing transaction promise.
- Product revisions intentionally exclude prices, inventory, variants/pricing/bundle financial composition and money history. General settings/Forum configuration and arbitrary Admin forms are not all versioned.
- Owner restore and the subsequent HTTP history/audit append retain the existing two-step contract; that whole sequence is not one atomic transaction. Current affected save paths are atomic. Multi-round moderation reopening/history is not a new case-event system in this batch; a decided case retains its first decision. Copyright takedown effects (2026-10-19) and Forum flag effects (2026-10-20) now commit with their decision and case in one transaction; notification delivery keeps its pre-existing owner boundary.
- ASS rendering follows the [official ASS.js DOM renderer](https://github.com/weizhenye/ASS); it is not a libass pixel-equivalence promise. Unsupported codecs/DRM/server transcoding and styled native PiP overlays are outside browser support. The exercised local fixture formats are H264/AAC, WAV and ASS, not every remote host/codec.
- 2026-10-20 format evaluation (4-second ffmpeg fixtures in a plain `<video>`, Playwright Chromium 153, Chrome 155 and Edge 155 on Windows 11): MP4/MKV/WebM with H264 (8- and 10-bit), VP9 and AV1 video and AAC, MP3, Opus or FLAC sound play everywhere. HEVC plays in Chrome/Edge here (system decoder) but not in the bundled Chromium, where the existing `videoWidth === 0` check shows the codec message. AC3, E-AC3 and DTS sound are **dropped without an error**: the picture plays silently, so the codec message never appeared; an MKV with AC3 plus an AAC track plays the AAC one. `player/SilentAudioNotice.tsx` now asks "صدای فیلم پخش نمی‌شود؟" under the picture after three seconds of unmuted playback with no decoded audio (Chrome/Edge counter; other browsers unchanged; HLS, embeds and a selected separate audio excluded), with the download link and the separate-audio hint. A file with no sound reads the same, so the notice asks rather than asserts. Verified on the real `/watch` page in Chrome and Edge at 1440 and 390 px (AC3 and silent files ask, AAC does not, muted playback does not). No transcoding or server-side probing was added.
- Notification integration is first publication through the current title save/bulk paths, not a release-date reminder for every followed film or a historical backfill.100-recipient continuation is tested; internet email/SMS/push delivery is not.
- Full module-off browser combinations, all opposed merge race schedules, broad Admin field-level conversion and production-size performance/load are not certified by these scoped tests. Existing module/identity guards remain authoritative.
- Local Graphify adapter/tool assets are absent in this worktree; source/Serena were used. No graph freshness or token-savings measurement is claimed.
