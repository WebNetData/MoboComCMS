## Limits and next deployment work

- An OS/application/database service must be bootstrapped before the web installer can run. It does not create a VPS from a browser. Initial HTTPS needs the reverse proxy or host setup before production login.
- Root helpers must be installed or refreshed by the operator on Ubuntu. Containers/Coolify keep their existing deployment/proxy boundaries; do not mount a Docker socket or grant a public web container unrestricted host root access.
- DNS issuance currently supports the existing Cloudflare provider, including ordinary domains. Other providers can supply externally obtained PEM files; no second generic DNS credential registry was introduced.
- Real DNS propagation, HTTP/standalone challenges, trusted public chain, Certbot renewals and Nginx reload must be exercised on the target host. Standalone requires port80 to remain free for renewal; the panel never silently stops another service. Manual certificates need manual replacement and private certificate backups.
- Imported leaf/key/SAN/time validation is not a public CA trust certification. Replacement checks cover the existing managed sites' names; operators still verify the complete chain with clients.
- Existing backup worker/config/retention/restore-test behavior is preserved. Backup permissions require server.manage and settings.manage on this new entry point. Database backups do not cover uploads/runtime secrets by themselves; retain those separately and retain encryption keys off-host.
- Updater acceptance used temporary Git repositories and command doubles for install/build/restart/health failure scenarios; it did not install a release on the owner's running site. Signed-tag enforcement is opt-in and needs trusted Git keys. App rollback can refuse if the checkout becomes dirty during the operation; database rollback is never automatic. No zero-downtime guarantee.
- Pending earlier migrations stay registered/unreleased. Release through the existing safe migration process; do not reset databases, reseed installed sites, change production URLs or drop archived content.
