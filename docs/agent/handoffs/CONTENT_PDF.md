## Delivered behavior and ownership

Content owns `src/modules/content/domain/pdf.ts`, the semantic document projection and `src/modules/content/server/pdf.ts` public address. Its folder separates authorized editorial/media/catalogue/community adapters, settings/history, assets, drawing, eight cover compositions, rendering and HTTP. Billing's existing PDFKit/Vazirmatn/visual-order approach is reused; invoices remain Billing's owner. The renderer/source adapters load only for an actual export, not while rendering a public action button.

The default-on `content-pdf` extension adds **محتوا → طرح و واترمارک PDF** at `/admin/content-pdf`, permission `content-pdf.manage` OR existing `settings.manage`. Eight typed designs are individually assignable to fourteen kinds: article, page, product, movie, series, game, software, track, album, playlist, forum post, prompt, public profile and business. Cinema uses actual MOVIE/SERIES state, independently. Every visible forum reply has its own export; a topic reference exports only its opening post, explicitly labeled. Public profiles contain their full public bio, not account or representative details.

Admin controls the global/per-kind switches, design assignments, brand/footer, A4/Letter, body size, content images, QR and text/local-image watermark. Watermark controls include opacity, size, angle, color and center/repeat/bottom position. Actual native sample previews use saved settings. `content.pdf.v1` uses existing transactional Settings CAS/history/audit, preserves unknown metadata and merges sparse per-kind patches. HTTP writes require Origin and honor If-Match. Existing content history restores settings through this owner.

Published content pages use the existing action bar; custom pages, playlists, forum posts, prompt templates, business and combined celebrity profiles compose the same download control. Public `GET /api/content-pdf/<type:id>` checks current standing, module, global/section maintenance, section/item/album audience, publication, existing paywall purchase/VIP/tier/drip and forum visibility before rendering body/assets. No draft body, original audio/download address, archive password, digital code or member generation is projected. Responses are private/no-store with an attachment filename. Existing aliases/permalinks supply the source link/QR.

PDFs contain selectable Persian/mixed Latin text, embedded Vazirmatn, headings/bookmarks, paginated paragraphs/lists/quotes/code/tables, supported images, linked source/QR, page numbers, update date and every-page watermark. Effects are native vector shapes/gradients. Original content and theme markup are never rewritten. Templates cannot run administrator HTML/CSS/JavaScript.

## Operation, limits and rollback

۱. از «محتوا → طرح و واترمارک PDF» طرح هر نوع محتوا را انتخاب و ذخیره کنید. فیلم و سریال مستقل‌اند.
۲. واترمارک متنی یا لوگوی عمومی کتابخانه را انتخاب کنید؛ پیش‌نمایش از تنظیمات ذخیره‌شده استفاده می‌کند.
۳. دانلود از همان صفحهٔ مطلب/محصول و برای پست‌های قابل‌مشاهدهٔ تالار انجام می‌شود. تغییر تنظیمات روی دریافت‌های بعدی اثر دارد؛ فایل قبلاً دانلودشده تغییر نمی‌کند.
۴. غیرفعال‌کردن نوع محتوا یا افزونه، دکمه و مسیر دریافت را می‌بندد؛ داده و تنظیمات حفظ می‌شوند.

This is a reading/catalogue export, not a screenshot of a theme or an interactive media archive. Audio/video/embed/interactive functionality stays online. Source images that cannot be safely read get an online-image notice; an unavailable configured logo watermark fails503 instead of producing unwatermarked bytes. A privileged preview demonstrates layout, not access to any private content. Watermarks are visible branding, not DRM.

Limits reject oversized documents: 80 pages, 16 unique content images, 8MiB/image with pixel/time bounds, 30MiB PDF, 240k text characters/5k semantic blocks, bounded child lists/table sizes, strict8/IP/min download limit, two concurrent renders per process. Oversized content is rejected, not silently exported as a truncated article. QR labels may wrap to two visible lines; their hyperlink retains the full source address. Very large titles are rejected if they cannot fit a readable cover. No new renderer service, package dependency, external PDF provider, migration or production deployment. Disabling the extension is the reversible rollback.
