## Implementation and trust

- `scripts/release-package.cjs`: bounded MBCREL01 envelope; Ed25519 verifies exact manifest bytes, payload size/hash, root-owned immutable public-key anchor. Streamed payload copy; partial output removed on failure. Stable semantic versions; source inventory detects local edits/new files while ignoring runtime data.
- `scripts/build-release-package.cjs` + `deploy/ubuntu/release-extract.py`: publisher uses immutable local Git HEAD, filters runtime/secrets/agent/cache content, emits `.mbrelease` and self-contained `.run`/public key/checksum. Publisher's private key never ships. Bootstrap is trusted executable installation media; distribute over the owner's authenticated HTTPS/SCP channel and verify checksum out-of-band. No live distribution URL is invented.
- `install.sh --package/--public-key`: package path needs no destination Git/GitHub. Root validates/extracts signed source into private staging, installs reviewed root assets separately, pins publisher key without silent replacement, initializes source inventory for a new installation and enables the existing password-bound web Server Panel. Legacy clone installation stays supported. Existing code/env/DB/custom Nginx are preserved.
- Fixed root-owned `mobocom-update package <sha256-id>` launches the service-user `package-update.sh` outside the app cgroup. Verifier/extractor/worker are installed under `/usr/local/lib/mobocom`, key under `/etc/mobocom`. Root only controls exact service lifecycle commands; no uploaded root shell. Normal Admin cannot change the trust key.
- Worker claims existing storage/update lock, privately recopies/reverifies package, checks source inventory, builds separately, takes mandatory current host backup, stops app, adopts code while preserving storage/var/env/.git, restarts and checks real readiness. Failed adoption/health restores old code; old health failure stays failed. No DB rewind. Previous code/staging retained privately for operator recovery; power loss is not a transactional filesystem/database promise.
- `updater/server/{packages,package-http}.ts` and private child route: fresh Server Panel unlock + current existing permissions, strict rate limit, streamed 512MiB body cap even with missing/lying length, bounded two-package admission and single-start claim, private persistent staged list/delete, repeated verification and audit. Existing JSON operation route has an8KiB cap. Private state never joins public Media/Library.
- Exact binary route streams outside Next Proxy's10MiB buffered clone; its handler applies the same canonical install/origin policy, module/access/unlock guard and private security headers itself. Cookie-only/foreign writes are refused. No global proxy/body limit was weakened. Nginx template has a matching private512MiB streaming location. [Next documentation](https://nextjs.org/docs/app/api-reference/config/next-config-js/proxyClientMaxBodySize).
- Existing status/progress API gains additive package method. Package mode skips GitHub and Git SHA/feed calls entirely, including cached GitHub results. Git/tag, Docker and webhook methods remain. Admin UI uses existing ServerShell/SDS classes, confirmation, staged version/hash/fingerprint, retry/error/loading and progress; protected public surfaces unchanged.

## Operator limits and next checks

Fresh Ubuntu22.04/24.04 systemd/UFW/DNS and real certificate issuance/renewal still require a destination VM. Packages need OS/npm network access, not GitHub; this is not offline dependency installation. Existing customized Nginx/env need explicit adoption per [operator guide](../../UPGRADE-FA.md). A legacy app without this API first upgrades through its old deployment path. Existing no-Git installations without an inventory need explicit operator source adoption, not silent acceptance of edited code.

Upgrade only accepts a newer stable version. Logical bugs that pass health require reviewed operator code recovery from retained snapshot; DB/schema compatibility is checked per release. Historical schema restore remains the explicit last-resort flow in [host recovery](HOST_INSTALL_UPGRADE.md). Failed build/staging and old code can consume disk; operator cleans only verified private paths after acceptance. Publisher key rotation and privileged helper format upgrades remain root/operator actions. Do not expose signing private keys, mutate production data for tests or claim production verification from fixtures.
