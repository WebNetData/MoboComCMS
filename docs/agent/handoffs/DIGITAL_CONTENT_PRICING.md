## Owners and contracts

- Account's domain/price-adjustments.ts owns integer PRICE/PERCENT/AMOUNT/FREE normalization and math. Percentages are basis points; Persian/Arabic digits and currency precision are validated. Lowest eligible price, including the ordinary price, wins; adjustments never stack or raise the ordinary price. Active, unexpired custom groups and current VIP participate. Existing fixed group prices and global group benefits remain compatible.
- Store keeps Product, ProductGroupPrice, existing cart/checkout/orders/invoices/wallet and delivery jobs. ProductGroupPrice.mode defaults to PRICE; priceMinor retains its column and means the validated integer value for that mode. Product.vipPricing is empty for legacy fallback, a validated rule for an explicit policy, or the JSON null string for explicitly no VIP rule. The old member price cannot silently reappear after removing an explicit rule.
- Paywall's PaidItem.pricingRules defaults to an empty array. Its existing post/software/game/title/album/track/link owners remain; prompt is added. A manager's existing section permission is required, including prompts.manage. Ordinary authors cannot price. Configuration can be prepared while Paywall is off, with an activation notice; module-off semantics are preserved.
- Price commands lock the canonical owner row, recheck current authority, validate groups/revision and commit strict audit with the change. Product authority is cms.products. Advanced price writes require an exact snapshot revision. Older fixed-price inputs remain supported but cannot silently overwrite advanced modes.
- Checkout accepts an optional additive expectedQuote (amountMinor/currency). The server recomputes the price and returns PRICE_CHANGED before money writes when it differs. Old callers remain compatible. Product instant buy, content buy and individual paid-link rows send their displayed quote; canonical cart validation remains in place. The instant-buy button waits for session resolution, avoiding a premature login redirect caught in the browser run.
- Free VIP/group eligibility is live and creates neither an order nor a permanent ContentPurchase. Paid purchases survive group expiry. Current linked Order and Invoice must remain PAID; refunded returned product lines close their purchase eligibility. ADMIN gifts and legacy orderless content grants remain supported. A refunded content purchase can be bought again by conditionally restoring its existing canonical grant; historical orders remain.

## Private files

ProductFile belongs to a Product through a restrictive FK. It stores a named attachment, opaque unique key, integer byte length, hash and active flag. The existing virtual digitalMode gains FILES, limited to fixed-price non-service digital products with an active attachment. Zero prices in Store are allowed only for FILES; no zero-value code/physical/service order is synthesized. All-file orders finish through the existing claimed delivery transition; mixed orders retain their original workflow.

Media owns streaming private-file I/O at media/server/private-files.ts. Bytes live in storage/private-media outside the public Library/download roots. Raw uploads are bounded, timed, hashed and aborted safely; failures clean the newly allocated orphan. Filesystem containment, regular-file/size checks and no-follow opening protect reads. Downloads use attachment/octet-stream, nosniff, sandbox, no-store and noindex, with GET/HEAD/range/suffix/416/abort support.

The product editor supports upload, explicit private copy of an owned/authorized local Library asset, title edit, archive/restore and FILES mode. Library copies leave the original public. Size/time limits reuse Media settings; no second storage settings service. Remote connected Library assets must first use the existing transfer-to-local flow. Private bytes are not listed as public MediaAsset URLs. Product deletion deactivates products with private files instead of deleting their rows/bytes.

GET /api/store/files/:id authorizes the current user, module/section maintenance, publication, item audience and current free eligibility or verified unreturned paid purchase before opening storage. Neither the storage key nor physical path is a public projection. This is account-based delivery, not DRM against an authorized recipient saving the file.

Store's existing /products?kind=VIRTUAL&files=1 filters only active FILES products with attachments. Entry title, description and visibility reuse Store settings. Product detail and order detail compose ProductDownloads; custom product templates that omit product-tabs still receive the necessary download panel. Existing URLs and protected layouts remain.
