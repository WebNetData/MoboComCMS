# Happ Site Studio

این نسخه، لایه ظاهر و محتوای سایت را از فروشگاه، مالی و مدیریت اشتراک جدا می‌کند.

## استفاده از پنل

- `/admin/studio`: ویرایش محتوای فارسی و انگلیسی صفحه اصلی، نمایش/پنهان‌سازی و ترتیب بخش‌ها، افزودن بخش، منوها، برند، اطلاع‌رسانی، انتخاب و شخصی‌سازی قالب و فعال‌سازی افزونه‌ها.
- `/admin/forms`: ساخت فرم، تعریف فیلد و گزینه‌ها، ترتیب فیلدها، الزامی‌بودن، پیش‌نویس/انتشار، پیام موفقیت و صندوق پاسخ‌های صفحه‌بندی‌شده.
- `/forms/{slug}`: نشانی مستقل فرم منتشرشده. با افزودن بخش «فرم سفارشی» و واردکردن slug، همان فرم در صفحه اصلی نمایش داده می‌شود. فرم پیش‌نویس نمایش داده نمی‌شود و پاسخ نمی‌پذیرد.
- اطلاعات پلن، محصول، مقاله، موقعیت شبکه و صفحه مستقل از مدیرهای موجود خوانده می‌شوند؛ در استودیو لینک مستقیم هر مدیر موجود است.
- تغییرات استودیو تا کلیک «انتشار تغییرات» اعمال نمی‌شوند. پیش‌نمایش داخلی نسخه ذخیره‌شده را نشان می‌دهد.
- دسترسی استودیو و قالب/افزونه: `settings.manage`؛ دسترسی فرم و تمام پاسخ‌ها: `cms.pages`.

## نصب قالب

یک قالب JSON مستقل، شامل `id`، `name`، `description`، `version`، `radius` و `colors` است. نمونه قابل نصب در `public/themes/example.json` قرار دارد. از تب قالب‌ها آن را وارد و منتشر کنید. رنگ‌ها باید hexadecimal شش‌رقمی و radius بین ۰ و ۳۲ باشد. قالب‌ها از طریق قرارداد `--site-*` روی صفحات عمومی و پنل‌ها اعمال می‌شوند؛ متن‌ها و داده‌ها دست‌نخورده باقی می‌مانند.

قالب JSON یک بسته هویت بصری (رنگ‌ها و شعاع گوشه‌ها) است؛ فایل ZIP قالب PHP/WordPress یا کد قابل اجرا را نصب نمی‌کند. برای چیدمان متفاوت React، renderer جدید را به صورت ماژول توسعه دهید. قالب‌های همراه پروژه در `src/themes/registry.ts` ثبت می‌شوند. حالت روشن دسترس‌پذیر نیز از کنترل موجود سایت قابل انتخاب است.

## توسعه افزونه مستقل

هر افزونه پوشه مستقلی در `src/plugins/<id>` دارد و یک `SitePlugin` صادر می‌کند. قرارداد در `src/plugins/types.ts` تعریف شده است:

```tsx
import type { SitePlugin } from '../types'

export const myPlugin: SitePlugin = {
  id: 'my-plugin',
  name: 'افزونه من',
  description: 'توضیح کوتاه قابلیت',
  version: '1.0.0',
  slot: 'after-footer',
  Component: ({ site, locale }) => <div>{site.brand}</div>,
}
```

افزونه را در آرایه `plugins` در `src/plugins/registry.tsx` وارد کنید، پروژه را دوباره بسازید و از پنل فعال کنید. جایگاه‌های فعلی `before-header` و `after-footer` هستند. نمونهٔ کامل announcement همراه پروژه است (دکمهٔ شناور support-dock به خواست مالک در ۱۴۰۵/۰۸/۰۶ حذف شد). منطق فعال/غیرفعال‌بودن در `PluginOutlet` متمرکز است و تغییر هسته فروشگاه نیاز نیست.

کد این جایگاه‌ها در مرورگر رندر می‌شود؛ اسرار، دسترسی دیتابیس و کلیدهای API را وارد افزونه نمایشی نکنید. برای قابلیت سمت سرور، route و سرویس مجزا با `requirePerm` تعریف کنید. افزونه‌های کدنویسی‌شده هنگام build ثبت می‌شوند؛ آپلود و اجرای کد ناشناس از پنل پشتیبانی نمی‌شود.

## مدل داده و گسترش

- تنظیمات صفحه در رکورد `Setting` با کلید `site.config.v1` به صورت نسخه‌دار و یکجا ذخیره می‌شود. داده پیش‌فرض در `src/lib/site/defaults.ts` و قراردادها در `types.ts` هستند.
- فرم‌ها در `SiteForm` و پاسخ‌ها در `FormSubmission` ذخیره می‌شوند. پاسخ شامل عنوان فیلد در زمان ارسال است؛ تغییر فرم، معنای پاسخ‌های قدیمی را از بین نمی‌برد.
- `src/components/site/LandingPage.tsx` نمایشگر بخش‌هاست؛ برای نوع جدید، type، validation، default، editor و renderer را همزمان اضافه کنید.
- لینک‌های تنظیمات و فایل‌های قالب سمت سرور اعتبارسنجی می‌شوند. HTML/JS دلخواه در تنظیمات اجرا نمی‌شود.
- پاسخ‌های فرم فقط از API ادمین خوانده می‌شوند. فیلدهای ورودی، ایمیل، گزینه‌ها و اندازه درخواست سمت سرور بررسی می‌شوند؛ honeypot و محدودیت ۵ درخواست در دقیقه برای هر فرم/IP موجود است.
- محدودکننده فعلی در حافظه هر پردازش است. برای استقرار چند نمونه‌ای، آن را به ذخیره مشترک (مثل Redis) انتقال دهید و فقط هدر IP پراکسی مورد اعتماد را بپذیرید.
- دریافت فایل تنظیمات برای بایگانی از تب برند موجود است؛ بازگردانی تنظیمات از فایل در رابط این نسخه ارائه نشده است.

## اجرای محلی و تست

```sh
npm install
npm run db:push
npm run typecheck
npm run test:site
npm run build
npm run dev
```

خروجی محیط توسعه در `.next-dev` و خروجی build در `.next` است تا اجرای همزمان پیش‌نمایش و ساخت، فایل‌های هم را تغییر ندهند. در ویندوز خروجی معمولی `next start` و در لینوکس بسته `standalone` ساخته می‌شود.

قبل از تغییر schema از دیتابیس نسخه پشتیبان بگیرید. در این توسعه نسخه قبلی دیتابیس به نام `prisma/dev.before-studio.db` حفظ شده است. از `db:seed` روی داده واقعی برای نمایش دمو استفاده نکنید. پرداخت و اتصال به پنل خارجی به تنظیمات واقعی محیط نیاز دارد و با این تغییرات بازنویسی نشده است.

صفحه اصلی تعداد کشور/موقعیت را از دیتابیس می‌خواند. گرافیک شبکه تزئینی است؛ وضعیت لحظه‌ای، uptime، پینگ یا تعداد کاربر ساختگی نمایش نمی‌دهد.
