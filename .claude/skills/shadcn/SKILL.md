# shadcn guidance for MoboCom

First verify the target actually uses shadcn and determine the component's local owner and installed base. Use existing accessible composition and variants. Check input labels, invalid/disabled state, overlay titles, focus, keyboard behavior and the current theme. Prefer existing components and use the official documentation for the actual API and base. For MoboCom surfaces using its own SDS primitives, follow their rules.

This text adaptation omits dynamically executed CLI context, permissive tool declarations, package/registry installs, presets and showcase generation. A runtime library or token migration is a separate architecture decision.
